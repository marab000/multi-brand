# Железные правила стилей

Действуют на **весь новый код** (старый мигрируем отдельными задачами). Правила не обсуждаются
в ревью — если значения нет в шкале/палитре, его нельзя использовать. Нужен новый токен —
добавляется в `variables.scss` один раз, а не хардкодится на месте.

## 0. Главный принцип: симметрия и UI/UX-здравый смысл

- Одинаковые блоки — одинаковые отступы сверху/снизу и слева/справа. Парные элементы —
  одинаковые размеры. Зеркальные зазоры разной величины — это **баг**, а не стиль.
- Ритм страницы строится на одной шкале (см. §2). «Подкрученные на глаз» 4px/6px/14px запрещены.
- Перед коммитом посмотри на блок целиком: равенство зазоров, выравнивание краёв,
  одинаковая высота парных элементов.
- Следуем правилам UI/UX, а не вкусу: интерактивный элемент выглядит кликабельным,
  у текста достаточный контраст, фокус всегда виден.

## 1. Цвета — только из палитры проекта

Бренд (SCSS-переменные из `variables.scss`, доступны в любом компоненте):

| Токен | Hex | Применение |
|-------|-----|------------|
| `$green` | `#0f3d1f` | рамки/текст брендовых контролов, hover |
| `$green-light` | `#3e6f4f` | основные кнопки, чекбоксы, фокус, ссылки-акценты |
| `$yellow` | `#e6a73c` | вторичные кнопки, бонусные блоки |
| `$error` / акцент | `#e31b23` | цены со скидкой, акции, удаление |
| `$success` | `#008000` | успех |

Нейтральные (фиксированный список, hex в scoped SCSS):

- текст основной `#111827`, второстепенный `#374151`, `#475569`
- приглушённый `#6b7280`, `#94a3b8`
- границы `#e4e7ec`, `#eee`
- фоны `#fff`, `#fafafa`, `#f8fafc`

Новые цвета «на глаз» не заводить. Нет подходящего — добавляем токен в `variables.scss`
и используем везде через него. Нативные браузерные акценты (чекбоксы, фокус) перекрыты
глобально в `controls.scss`/`layout.css` — не возвращать синеву.

## 2. Размеры и отступы — шкала 4px, mobile-first, ВСЕГДА адаптивные

Отступы пишем **tailwind-классами** (приоритетный способ) и **всегда парами**
«мобилка → десктоп»: на мобилке меньше, на десктопе больше. Одинаковое значение на всех
экранах — исключение (только мелкие gap-1/gap-2).

```html
<div class="my-3 lg:my-4 p-3 lg:p-4 flex flex-col gap-3 lg:gap-4 mb-3 lg:mb-4">
```

Базовые пары (заучить):

| Что | Классы |
|-----|--------|
| карточка/блок, паддинг | `p-3 lg:p-4` (12 → 16, = `@include card-padding`) |
| зазор между связанными элементами | `gap-2` (8px везде) |
| зазор между блоками | `gap-3 lg:gap-4` (12 → 16) |
| внешний отступ блока | `my-3 lg:my-4` / `mb-3 lg:mb-4` (12 → 16) |
| отступ между секциями | `mt-4 lg:mt-6` / `mb-4 lg:mb-6` (16 → 24) |

- Голые `margin/padding: 16px` в scoped SCSS запрещены, когда можно классом — класс в
  разметке наглядно показывает, откуда отступ и как он адаптируется.
- Если в SCSS неизбежно (вложенные селекторы, динамика) — токены `$sp-1..8` и
  `@media (min-width: …)` с десктопным значением. Никаких сырых px.
- Запрещённые значения: 5, 6, 7, 10, 13, 14, 18, 20px и любой другой офф-скейл.
  Исключения: `1px` границы, `2px` мелкие детали, `999px` пилюли.

Адаптив всегда **mobile-first**: базовое значение — мобилка, десктоп — через префикс
`lg:` либо `@media (min-width: …)`. `max-width`-медиа в новом коде запрещены.

## 2.1. Отступы задаёт РОДИТЕЛЬ через gap, а не дети через margin

- Список/колонка элементов? Родитель получает `flex flex-col gap-2`, `gap-3 lg:gap-4` —
  а дети НЕ имеют своих margin-top/margin-bottom. Это единственный способ гарантировать
  симметрию: между всеми детьми одинаковый зазор, ничего не «прилипает» и не разъезжается,
  когда ребёнок добавляется/удаляется/прячется.
- `my-*` у ребёнка разрешён только для независимых секций страницы (блок ↔ блок), не внутри
  колонки из однородных элементов.
- Никакой «хаотичной раздачи»: у одних блоков margin-top, у других margin-bottom,
  у третьих и тот и другой — так не делаем. Если ловишь себя на `mt-3`, а сосед уже
  `mb-3` — убирай оба и ставь gap родителю.

### Проверка перед «готово» (обязательная, не опциональная)

1. Открыть компонент на **390px и 1400px** (обе раскладки, не одну).
2. Замерить зазоры между всеми соседями в колонках (DevTools или скриптом):
   одинаковые дети — одинаковые зазоры, нулевых зазоров нет.
3. Скриншот обеих раскладок глазами.
Только после этого писать «готово».

## 3. Брейкпоинты — только 4 каноничных

`sm 640 / md 768 / lg 1024 / xl 1280` — и в tailwind-префиксах, и в `@media (min-width: …)`.

Самодельные (1023, 639, 560, 520, 900, 1000, 1100 …) запрещены.

## 4. Tailwind vs scoped SCSS

- **Tailwind**: геометрия и раскладка — flex/grid, gap, padding/margin, width, align.
- **Scoped SCSS** (`<style lang="scss">`): цвета, типографика, hover/focus-состояния,
  сложные компоненты.
- BEM обязателен в scoped-блоках: `.block`, `&__element`, `&--modifier`.

## 5. Радиусы — только 8 / 12 / 16 / 999 / 50%

| Значение | Где |
|----------|-----|
| 8px (`rounded-lg`) | мелкие контролы, инпуты, теги |
| 12px (`rounded-xl`) | карточки, кнопки-пилюли контейнеры |
| 16px (`rounded-2xl`) | крупные секции, модалки |
| 999px (`rounded-full`) | чипы, бейджи, аватары-пилюли |
| 50% | круги |

6, 10, 14, 18, 20, 22px — запрещены.

## 6. Типографика

- В SCSS размеры пишем в **rem**: `0.75rem` метки, `0.8125rem`/`0.875rem` текст,
  `0.9375rem`/`1rem` акценты и заголовки карточек.
- h1–p — глобально из `typography.scss`, локально не переопределять размер без причины.
- Веса: **700** заголовки/акценты, **600** подзаголовки/кнопки, **500** подписи/второстепенные
  кнопки, **400** текст.
- Приглушённый текст — класс `text-secondary` (или `#94a3b8` из палитры).

## 7. Контролы — общие, не самописные

- Кнопки: `.btn .primary` / `.btn .secondary` / `.btn .secondary-with-border` из `controls.scss`.
- Инпуты: `.input` (+ модификаторы). Чекбоксы/радио: глобальные нативные стили или `.checkbox`.
- Свои копии стилей кнопок/инпутов внутри страниц запрещены.
- Паттерн повторился третий раз → вынести в компонент или `controls.scss`.

## 8. Переходы

- Только `transition: 0.15s ease` (мелкие) или `0.2s` (кнопки/крупное).
- Свойства: `background`, `border-color`, `box-shadow`, `color`, `transform`.
- `transition: all` запрещён.

## 9. Чек-лист перед коммитом

1. Все отступы из шкалы 4px (`p-3 lg:p-4`, `$sp-*`)?
2. Брейкпоинты только 640/768/1024/1280, адаптив mobile-first?
3. Цвета из палитры §1?
4. Парные отступы и элементы симметричны?
5. Контролы из `controls.scss`, а не самописные? Радиусы из §5?
